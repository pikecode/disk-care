## 使用

打开已交付的 `release/留白.app`（重新构建的产物位于 `src-tauri/target/release/bundle/macos/留白.app`），点击「开始扫描」，选择可清理项目，预览具体命令及影响，再确认执行。不会自动勾选，也不会自动清理。

扩展扫描在规则清单之外，提供用户主目录、`/Applications`、`/opt`、`/Library`、`/private/var`、`/System/Volumes/Data/System`、`/Users/Shared` 和 `/usr/local` 八个主要目录的只读分析。两层清单存在包含关系，不应相加。支持 uv、npm 下载缓存和 pip 缓存的官方清理命令；Yarn、Gradle、Poetry、pnpm、应用缓存、下载文件、Ollama 模型仅分析。0.8.3 起主动跳过常见其他应用私有数据目录，Docker 与企业微信容器不再默认读取；展开目录、自定义缓存和项目扫描遵循相同边界。模型清单从本地读取，不会启动 Ollama。uv/npm/pip 通过自身查询命令发现实际缓存位置；配置查询失败时禁止清理，自定义路径和遗留默认目录只读列出。查询以桌面进程环境和主目录配置为准，不推断各项目单独配置。

进入「项目账本」，确认扫描范围后扫描项目，再展开「本地模型空间账本」。项目扫描同时只读分析 `~/.ollama/models` 默认仓库，展示文件块去重占用、已发现共享占用、清单范围内独占占用与项目配置引用。自定义仓库暂不支持；独占不表示未使用，模型仍不提供删除操作。统计不完整时隐藏独占结论，模型占用不加到项目产物或可回收量中。

0.9.2 以 uv 默认缓存作为首个清理依据样板：展开详情查看独立规则编号、识别来源、处理范围和恢复条件；可保护整个默认缓存目录，设置在本机保存，保护后只读分析。解除保护或改变设置后需重新扫描；本版不支持子目录排除，也不清理自定义缓存。

uv 扫描、预览和执行前比较目录元数据摘要，发现变化或复核不完整时要求重新扫描。摘要不读取文件正文，不等于内容校验、目录锁或没有依赖的证明。所有清理继续复核配置、路径和本机可见进程，不自动终止运行程序。

扫描结果区分已扫描、不存在、主动跳过、访问拒绝、其他失败、超限、停止与尚未访问；仅在确认出现权限拒绝时显示结果页的设置入口。扩展扫描前仍保留按需授权说明，不自动改变系统权限。

每次清理区分命令完成、失败与未执行；uv 执行后重新测量目录，无法完成核验时明确说明。磁盘可用空间按增减展示，反映所测数据卷期间的变化，不能直接归因于清理；旧历史兼容读取。清理后扫描结果失效，需要重新扫描。

## 行为边界

- 不申请管理员权限，不删除数据库，不绕过认证。项目扫描有限读取根部配置（包括 `.env`）匹配已安装模型名，正文和凭据不返回界面、不写入基线；不扫描配置子目录或执行项目代码。
- 清理参数由 Rust 固定规则生成，前端只能传项目 ID 和预览凭据，不能传删除路径或任意命令。
- 清理路径拒绝越界、父目录跳转与符号链接；只读扫描不跟随内部符号链接、不跨文件系统，单项目内按设备号和 inode 去重。读取工具明确配置的缓存根时可解析其真实路径，重定位目录仅供分析。
- 缓存规则每项最多扫描 45 秒；主要目录和按需展开最多 300 秒，每项最多处理 500 万条。达到上限、权限受限或取消时标记不完整，清理项不会被自动放行。完整扫描可能持续数分钟，可停止。
- 目录浏览显示直接子项的子树分配空间并按大小排序，每页 200 项；支持继续加载和进入子目录，统计缓存有效期 5 分钟。过期后重新打开，避免拼接不同快照；中断后的结果只显示下限。
- 运行依赖检查区分可执行文件、解释器脚本与普通参数，支持版本化 pip 与 npm-cli.js，提示包含关联 PID。清理前再次复核；仍无法覆盖隐藏依赖或检查后的并发变化。
- 清理计划 60 秒有效且只用一次，失败后停止后续项目；命令超过 5 分钟则终止命令进程组，并提示可能已清理部分内容。
- 清理不可撤销。已有独立 Python 环境通常保留，但缓存内的临时工具环境需要重新创建；不要依赖“缓存”名称判断可删除。
- 容量由 `df -kP` 读取数据卷已用量，另外显示共享／保留空间，不再把总量减可用当作单卷已用。目录分配块估算与实际释放量仍可能不同，受 APFS 克隆、共享硬链接、快照、打开的文件及其他进程写入影响。
- 清理历史只存本机 `~/Library/Application Support/local.diskcare.desktop/history.json`，最多 100 条；不保存密码。项目基线存同目录的 `projects.json`，最多 20 个工作目录，保存产物路径、大小和时间，不含配置正文和进程参数；其余扫描结果在内存中保存。
- 项目发现最多 8 层、20,000 个目录、1,000 个项目、5,000 个产物，时间预算 120 秒；配置单文件最多读取 64 KiB。已识别产物目录内部不继续发现项目。缺少进程或配置引用不等于没有依赖，跨项目硬链接和 APFS 克隆可能重复计算，项目占用不能直接当作可释放量。界面每批显示 50 个项目。模型账本默认折叠，未完整统计或已停止会直接标注在摘要；文件块依据展开后每批显示 50 条。
- 关系图每批展示 12 个直接邻居，可继续显示。它只使用结构化证据：旧版文字说明不会被猜测成连线。进程关联项目不代表使用具体产物或调用某个模型；模型引用只覆盖本次扫描范围，缺少引用不代表无人使用。图形不开放额外删除权限。
- 模型扫描最多 5 秒、1,024 个清单目录条目、512 个模型和 8,192 个文件块引用；单清单最多 1 MiB，累计最多 8 MiB。逐级禁止跟随链接，只读取模型清单及文件元数据；硬链接按设备号和 inode 去重。超过限额、缺块或坏清单不判断独占，未归属硬链接也会阻止相应模型的独占结论。扫描不是原子快照，不检测所有并发变化或 APFS 克隆共享。
- 无后端网络服务、遥测、自动更新或后台驻留；npm 等官方命令仍遵循其自身配置。
- 当前只面向 macOS；未做对外发布所需的开发者签名与公证。

遵循 KISS/YAGNI：先完成三个明确清理规则，不增加通用删除引擎或插件系统。扫描、界面与执行入口分工，路径校验和执行流程复用。

详细验证范围见 [验证记录](docs/verification.md)。发布目录只包含本地应用与旧版备份；本轮保留 `src-tauri/target/` 编译缓存便于后续迭代。缓存不属于应用运行依赖，开发结束后可按需清理。

## 扩展扫描的目录选择与耗时

0.9.8可从后端内置的八个主要目录中选择本次范围，默认全选；也可取消全部，只分析扩展固定／发现项目。开发缓存、下载和默认Ollama模型等固定项目仍会读取，取消主目录不等于排除它的所有子目录。变更选择后需重新确认阅读；目录选项加载失败不能开始扫描，不自动回退全量。

结果列出实际主要目录和各阶段耗时，取消后未访问项目显示“尚未访问”，短耗时与未访问分开；旧报告无计时数据时不补造。运行中时间是界面等待观测，返回后的时间由后端测量。准备时间纳入总耗时，阶段耗时不表示完整性或预计剩余时间。主要目录与固定项目可能重叠，不能相加；本轮没有建立共享扫描索引，也没有新增删除规则。
