# 清理按钮、选择确认与实现差距

日期：2026-10-21。目标为本机 CleanMyMac 5.7.2，继续补证 [上轮界面研究](cleanmymac-clean-ui-re.md)。本轮完成定点静态研究及留白代码对照，不代表完整还原，也未交付新的清理能力。留白版本仍为 0.9.2。

## 主按钮绑定已接通

以下地址均为 ModuleCore arm64 虚拟地址。

| 环节 | 证据与行为 |
| --- | --- |
| 配置按钮 | `0xc08d4 setup(with:)` 将 footer 封装到闭包，赋给 `onPerformMainAction`，并接入按钮标题及可用状态发布器 |
| 点击转发 | 上轮 `0xc0868 performMainAction` 调闭包；本轮 `0xc3768` 调 footer 协议槽 `+0x40`，进入 `0xa4984 primaryAction` |
| 活动节点 | `0xa4984` 弱引用读取当前节点；有效时调用对象 `+0x40` 保存的动作，失效时仅记录日志 |
| 动作来源 | 构造器 `0xa4ce8 → 0xa58dc → 0xa50f4`。汇编 `0xa596c–0xa5988` 明确将 `0xa5acc` 作为动作参数；初始化保存到对象 `+0x40` |
| 管理器回调 | `0xa5acc → 0xa5a94 → 0xa4d4c`，弱引用读取数据管理器，调用其协议槽 `+0x30` |
| 具体实现 | witness 表 `0x17f280 + 0x30 → 0xc2e18`；该转发器调用类槽 `+0x2c0`；类 metadata `0x1a5970 + 0x2c0 → 0xc1700 runPrimaryAction` |

由此补上上轮缺失的 footer 到主操作检查入口。后续仍沿用上轮已核对的主操作检查、delegate 请求、清理页订阅及启动链。没有进入或绕过许可检查实现。

## 选择确认发生在选择事件中

复用上轮 `0xcd7e0 SelectionConfirmationCoordinator.activate`，结合本轮闭包及导入绑定：

1. 观察 `NodesCore.Selection.onStateChange`，通过 `dropFirst(1)` 跳过初始事件。
2. `0xce630` 只接受状态字节等于 `1` 的事件。尚未核实该枚举值的正式名称，不将它扩大解释为任意勾选变化。
3. 弱引用取节点，合并事件，以 `collect` 的时间分组收集；步长由 `milliseconds(50)` 构造。这里是时间分组，不是防抖。
4. `0xce640` 排除空数组，`0xcf638 → 0xce680 → 0xce6dc` 处理一批节点。
5. `0xce6dc` 遍历节点的确认描述，`0xcf0a0` 提取可用描述，向 presenter 调用确认。描述内部枚举编码尚未完整恢复，不能声称所有缓存选择都会弹窗，也不能声称合并了每个节点的提示。
6. presenter 返回接受则返回；拒绝则收集符合 Selectable 的节点，调用 `Selection.performBatchSelectionUpdate`，其闭包 `0x651ec` 逐项调用选择协议槽 `+0x18`。该槽的具体方法映射本轮未独立核实，因此只确认批量选择更新，不将“逐项 deselect”作为已证实结论。
7. 拒绝分支还向祖先节点遍历，对符合 `SelectionControlRepresentable` 的对象去重，向选择控件传入空的 `SelectionOption`。

这是选择层确认，不能代替最终执行授权。拒绝分支未看到文件移除或新清理任务提交。`NodeDataManagerViewModel.activate/deactivate` 调用的 `0xc1c70` 是默认选择快照相关逻辑，不能与上述 coordinator 生命周期混为一谈。

## 错误说明与剩余项目

`0x1109c CleanupLocalizedErrorMapper.description(from:)` 顺序尝试错误处理器：存在内部原因时先匹配内部错误，再尝试原始错误；没有匹配则返回空。此处证明描述映射策略，不证明具体权限错误文案、修复或自动重试。

`0x5e290 CleanLogViewModel.requestReviewRemainingItems` 在回调存在时调用它，再通知另一协议对象。结合上轮导航链，“查看剩余项目”可以返回数据界面；不能据此称为再次清理。详情页具体按钮布局、错误处理器的完整默认列表和重试入口仍未还原。
