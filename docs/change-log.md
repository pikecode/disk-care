## 记录规则

- 每轮功能、修复、视觉交互、配置、复测、文档调整或方案撤销，都增加一条记录；相同版本号也不能合并覆盖此前记录。
- 编号采用 `YYYYMMDD-NNN`，同日递增，最新记录放在最前。版本未变写明“未变”；规划和未发布改动明确标注，不能当成已交付。
- 每条记录包含背景、修改内容、涉及文件、验证、影响与限制、依据。失败、跳过和待实机确认的项目如实记录；不把模拟测试当成真实系统验收。
- 既有记录不因新版本发布而删除。纠错或补充证据应注明补充日期；后续修复另增条目并引用原问题。
- 一轮关联修改共用一条记录，日志自身的更新纳入该条，不递归生成新记录。只有文档调整时不为此升级应用或重新打包。
- 截图和日志目录 `output/`、应用目录 `release/` 是本地产物，可能因清理不可用；核心结论必须写入本文件或被链接的 Markdown 文档。
