# 项目直接关系图实施计划

> 用户已授权按规划在本会话实施。使用 writing-plans（实施规划）与 frontend-design（界面设计）；当前目录没有 Git 仓库，不创建提交或 worktree。

**目标：** 交付 0.4.0，提供基于真实结构化证据的项目/产物/模型/进程直接关系图，并保留账本。

**架构：** Rust Evidence 增加可选结构字段，保持原消息及扫描命令兼容；TypeScript 从报告生成节点/连线索引，React 用固定列布局展示一层关联和证据详情。关系图不调用删除接口，不将配置引用推断为实际调用。

**技术栈：** Rust、Tauri 2、React、TypeScript、内置 SVG、现有 CSS；无新增运行时依赖。

## 任务 1：后端证据与兼容

文件：`src-tauri/src/projects.rs`、`src/types.ts`、`scripts/project-ui-smoke.js`。

1. 给模型证据增加 model/source，进程证据增加 pid；未知证据这些字段为空。
2. 测试序列化字段、旧证据反序列化、正文和参数不回传；原检测逻辑保持不变。
3. 更新 TypeScript 类型和模拟数据，不在前端解析中文消息。
4. 运行 `cargo test --manifest-path src-tauri/Cargo.toml projects`，预期通过。

## 任务 2：可验证的图数据

文件：新增 `src/relationships.ts`、`scripts/relationships-check.ts`。

1. 按类型与标识组合 ID，项目路径保留完整相对层级；同名不同路径不得合并。
2. 合并模型、PID 和重复边，保留多份配置来源，忽略缺少结构字段的关联。
3. 图只从已有报告生成；不增加占用推算或隐含传递依赖。
4. 使用系统临时目录编译并运行 TypeScript 断言，覆盖共享模型、同名项目、重复配置、旧数据及方向，不新增测试运行库。

## 任务 3：关系视图

文件：新增 `src/RelationshipGraph.tsx`，修改 `src/ProjectLedger.tsx`、`src/style.css`。

1. 加入关系图/账本列表切换；项目列表可搜索、每批显示 50 项。
2. 一层关系按方向排布为左右两列邻居与中心节点，每批 12 个，提供继续显示及返回项目。
3. 节点和边均可选择；详情显示来源、恢复条件、已测量空间与范围限制；共享模型可反查多个项目。
4. 为节点与连线提供等价文本按钮及焦点状态；图例含文字、线型和颜色。
5. 部分报告、未知占用、无结构字段、空报告都必须明确呈现。

## 任务 4：验证与交付

文件：新增 `scripts/relationship-ui-smoke.js`，更新原项目页脚本、版本、README 和验证记录。

1. Playwright 模拟 IPC 检查共享节点、来源详情、中心切换、搜索、分页、键盘、切回账本、无删除调用及 960px 宽度。
2. 跑图数据断言、Rust 常规测试、严格 Clippy、TypeScript 构建和两套旧界面回归。
3. 本机只读扫描检查新证据接口，构建 0.4.0 app，保留 0.3.0 回退备份并核验原生启动。
4. 回填验证结果；清除本轮编译中间文件，不清理用户项目。
