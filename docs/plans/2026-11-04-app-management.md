# 应用管理与卸载反馈实施计划

目标：统一应用管理入口，保留页面选择与搜索，补齐卸载结果和本地操作历史。

方案一（采用）：沿用应用／详情双栏，在详情和历史中提供明确操作；复用既有确认与检查契约。方案二：另建卸载模块与独立列表，会重复身份选择和页面状态，本轮不采用。

KISS／DRY：复用列表、预览确认、路径校验与原子历史写入模式。SOLID：卸载历史独立于缓存清理账本。YAGNI：本轮不引入批量卸载和残留删除。

步骤：
1. 固定0.9.15验证原生应用管理前身入口和读取列表，记录实际覆盖；不操作已有软件卸载或系统权限。
2. 后端添加有界、原子保存的卸载历史（成功／执行失败、时间、原路径与恢复说明）；保存失败不能把已成功移动显示成卸载失败。
3. 入口改为“应用管理”，保留切页搜索与选择；详情区清晰提供检查／卸载，显示应用版本。结果区与历史可主动选用标识检查关联文件，不能自动执行。
4. 为历史读写、损坏／链接、写失败和成功／失败语义增加测试；浏览器验证导航状态、历史、确认与只读检查。
5. 打包并验证完整签名，同步记录。应用真实图标和更广检测规则另需有界原生读取方案，不混入本轮反馈功能。
