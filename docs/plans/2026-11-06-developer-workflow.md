# 开发工具账本交互完善与原生补验

依据：用户同意按推荐先补权限验收，再完善现有闭环。当前基线0.9.23。

方案比较：推荐工具列表＋所选工具详情，便于比较与单项重查；备选保留长卡片仅加排序，改动更少但无法解决多来源滚动。沿用现有设计样式、IPC和遍历机制，不新增依赖。应用KISS／DRY；观察与执行分离符合SOLID；按YAGNI不在本轮加入新清理规则、持久化增长与重复文件。

本轮范围：

1. 对固定0.9.23包补验系统选择取消、选定自建目录、确认分析及根目录拒绝。不能触发的系统授权／拒绝／重启项保留待验，不更改TCC。
2. 开发工具结果改为工具列表＋详情，按工具名称或最大单来源观测占用排序，不相加成工具总量。每工具独立观测时间、Rust项目范围快照。
3. 单工具重新检查与失败重试；沿用范围确认，重查只替换该工具，保留其他工具报告。整体请求失败保留旧报告并明确失败；来源级失败或取消以新状态呈现，不继承旧占用。Rust换项目时重置确认，旧报告保留原范围标签，不静默重标。
4. 详情支持来源筛选与占用排序，默认显示一个来源的解释，未知占用排后；报告切页保留，不自动探测。原生预览仍为独立显式动作。
5. 补前端断言及模拟IPC流程，运行相关完整检查，打包完整签名校验，保留旧版与修改记录。

验收边界：Finder定位需要后端报告身份及路径复核，留待下一独立步骤；不通过前端任意路径调用系统命令。普通扫描持久化增长与新工具清理另行实施，不因本轮原生选择通过就宣称M3全部完成。

## 执行结果

0.9.24本地交付第2～5项交互与验证；每工具报告保留独立时间及Rust范围，第七组断言和模拟IPC通过，Rust96通过／10忽略，打包及两处完整签名通过。第1项取消已补验；原生路径导航未可靠进入自建目录，首次误选Documents后的只读统计及样本断言失败已保留，第二次先核对路径而未分析。根目录拒绝／完整权限矩阵仍待验，不将第1项记为整体完成。

下一步：Finder定位需在后端保存来源身份并复核；新清理规则、增长记录与重复文件不纳入本轮交付。
