# 留白产品体验重构实施计划

**目标**：让首次使用者理解空间去向、可处理项及处理影响，无需先理解账本、候选、来源等内部概念。

**架构**：继续使用Rust／Tauri／React；按用户任务组织导航，复用既有扫描、报告、确认和执行接口。显示层调整不得新增删除能力或改变权限状态。

**技术栈**：现有React／TypeScript、CSS与原生dialog；不新增运行时依赖。

执行：沿用writing-plans、executing-plans和UI/UX工作流逐项实施；当前用户已授权文档与实施，不为阶段规划重复索取许可，不默认提交或发布。

## 设计判断与方案取舍

推荐“清理／空间／应用”三个主入口：对应释放空间、寻找大项、管理软件。历史为次要入口，开发工具／项目／AI数据归入空间。备选保留六模块仅统一视觉，成本更低但仍要求理解内部分类，因此不采用。

KISS减少顶层选择和操作步骤；DRY复用列表、详情、确认与报告，不复制引擎；SOLID保持观察与执行分离；YAGNI暂不加入重复文件、常驻监控、规则插件及新的删除规则。

## 页面职责

| 页面 | 主要任务与首屏 | 结果与后续操作 |
| --- | --- | --- |
| 清理 | 可用容量、一句目的、一个“开始检查”按钮 | 可以清理／可以查看／需要保留；实际执行仍逐项预览确认 |
| 空间 | “哪个位置占空间”，选择文件夹为主操作 | 文件夹／开发工具／项目／AI数据分类；复用最近结果，不因切页自动扫描 |
| 应用 | 搜索与应用列表，选中后展示详情 | 查看本体与关联数据、卸载；卸载保留独立确认和恢复说明 |
| 历史（次要） | 发生了什么、哪些成功／失败 | 可用空间变化独立陈述，不全部归因为清理 |

## 全局交互规范

- 左侧任务导航、中间对象列表、右侧所选详情；不要同时叠加多套卡片／筛选／详情入口。
- 页面只保留一个主操作；名称、占用、状态优先，路径／规则／预算按需展开。部分统计和拒绝访问直接可见。
- 不相加重叠账本，不用总占用暗示总可释放量；“可以清理”只用于已有合格执行规则。
- 普通只读范围以明确的操作前确认表示同意；新敏感范围单独说明。执行删除前展示具体目标、影响与恢复方式。
- 全产品使用系统字体与既有色彩，绿色聚焦主操作／选中状态，警告色只用于需关注状态。
- 取消／Esc回到触发按钮；Tab顺序和原生模态框保留；忙碌、失败、无数据、部分统计均有明确反馈。
