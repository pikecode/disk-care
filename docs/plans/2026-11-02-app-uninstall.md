# 应用本体卸载实施计划

**目标：** 用户明确确认后，将常规应用目录内选中的单个第三方应用包移到废纸篓，并提供卸载后只读关联检查入口。

**架构：** 独立卸载模块复用应用身份读取、任务互斥和退出保护；预览令牌绑定路径、标识、文件身份与有效期，执行仅接收一次性令牌。调用 macOS Foundation 原生废纸篓接口，不使用永久删除、不请求提权、不自动退出其他应用。

**技术栈：** Rust／Tauri／React；复用已在依赖树内的 objc2 Foundation／AppKit 绑定，直接声明所需能力。

## 方案

1. 推荐应用包移到废纸篓：单一明确目标，可通过 Finder 手动恢复，关联数据保持原状。
2. 应用及数据联合删除：需要共享归属、凭据保护和后台组件规则，当前不开放。带专用卸载器的软件优先使用厂商方案。

KISS：单应用、双阶段确认。DRY：复用身份、作业锁、退出保护和残留检查。SOLID：卸载与只读扫描分离。YAGNI：不做批量、自动杀进程、永久删除、后台服务清除或管理员提权。

## 实施顺序

1. `src-tauri/src/app_uninstall.rs`：白名单路径、包身份、父链／包／Info.plist 元数据快照、运行进程阻止（NSRunningApplication 标识＋proc_pidpath 完整路径）、自身及 Apple 标识保护；单次令牌有效期 60 秒。
2. `core.rs`／`lib.rs`：卸载计划状态与 prepare／execute IPC，执行期间阻止退出。使用原生文件引用 URL 绑定文件身份，执行前复核；失败不回退为永久删除。
3. `src/types.ts`／`api.ts`／`AppResidue.tsx`／`App.tsx`：详情区卸载入口，确认面板显示名称、精确路径、保留数据与恢复说明，取消不执行，任务中禁用竞争操作；成功后从列表移除该副本，保留标识供用户主动检查关联数据。
4. Rust 临时 fixture 验证路径越界、链接、身份变化、过期／错误／复用令牌、运行中、自身保护与执行失败；模拟 UI 验证无隐式卸载、确认、取消、错误恢复、成功后关联检查。
5. 统一检查、打包、完整签名校验，更新修改记录和验证；不卸载用户已有应用。只在临时合成包上验证原生废纸篓操作，并记录与真实产品包卸载的区别。

## 边界

应用移到废纸篓不等于彻底卸载，不释放已占用空间，不清空废纸篓，不终止后台服务。进程状态检查为执行时观测，不能阻止检查后新进程启动。Apple 标识保护是保守策略而非签名鉴定。系统权限不足原样失败；允许／拒绝权限矩阵继续待验。

依据：[Apple 卸载指引](https://support.apple.com/en-nz/102610)、[Foundation 废纸篓接口](https://developer.apple.com/documentation/foundation/filemanager/trashitem(at:resultingitemurl:))。

## 实施验证

实现预览／执行、原生废纸篓接口、一次性令牌、应用包及父链身份复核，确认框与卸载后主动检查入口。进程状态无法读取时保守拒绝，主窗口退出复用现有执行保护。

初次测试失败保留：运行辅助进程测试揭示 `ps comm` 可能截断路径，改为内核完整路径和 AppKit 标识双重检查；复制系统 sleep 的测试程序被系统终止，最终使用现场编译的临时 C 辅助程序确保进程确实存活。初次 UI 测试发现默认焦点落在勾选框，改为弹窗打开后显式聚焦取消按钮。修复后专项与完整检查均通过。

统一检查：83 项 Rust 测试通过、9 项忽略（其中 1 项为需单独手动运行的废纸篓测试），五组前端断言、构建、fmt、Clippy 通过。该废纸篓测试已另外运行通过：临时生成的应用包移到系统废纸篓，标记文件内容不变，再恢复到临时位置；未触碰用户已有应用。卸载 UI 与原残留 UI 两组模拟通过，不替代打包应用权限验收。
