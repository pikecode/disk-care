# 卸载前退出应用实施计划

目标：让用户在卸载被运行实例阻断时，明确选择正常退出，超时后独立确认强制退出；退出成功后仍重新预览并确认移到废纸篓。基于用户已认可方案执行。

方案比较：按名称／PID批量kill简单但会误伤，不采用；推荐NSRunningApplication正常／强制退出，只处理可执行文件真实位于所选包内、有启动时间的系统应用实例。系统未登记的命令行进程、其他副本或仅打开目标文件的第三方不结束，原占用保护继续阻断。没有管理员提权或关闭启动服务。

1. 复用应用身份、系统／自身保护、文件快照和作业锁；新增退出预览与执行命令，前端不提交PID。60秒一次性令牌绑定包快照、进程PID／启动时间／可执行路径和身份。拒绝目标替换、进程替换、旧令牌、直接强制跳过正常退出。
2. 使用系统实例API请求正常退出，最多等待3秒；仍有实例时返回新的可强制退出预览，独立提示未保存资料风险并勾选确认。强制退出不循环追杀自动重启进程；结束后再次读取现状，仍被占用就阻止卸载。
3. App.tsx保持统一任务状态，AppResidue错误区域加入“退出应用后继续…”；独立对话框列出目标进程及位置、默认取消、Esc取消／焦点返回。正常退出不等于卸载授权，退出成功仅重新打开原卸载预览。
4. Rust测试验证身份／路径边界、令牌／强制阶段、过期／重放和替换拒绝；浏览器模拟验证取消零退出、正常超时后强制、独立勾选、目标切换和重新卸载确认。用自建原生应用核验正常退出、拒绝正常后强制及无关进程存活。
5. 统一检查、十一组模拟、应用构建与完整签名；保留0.9.36，交付0.9.37。记录实际边界，本地归档不自动推送。

工程原则：KISS复用系统实例接口，不增加通用进程管理器；DRY复用安全校验与现有卸载流程；SOLID退出能力独立模块／对话框；YAGNI不实现提权、启动项管理和全机进程终止。未知实例继续保守拒绝。


实际结果：0.9.37本地交付；统一检查105通过／10忽略，十一组模拟通过，最终包签名通过。四实例原生范围与正常／强制退出验证、临时应用废纸篓往返通过；自建夹具清除。首次现有AppKit依赖未启用libc特性导致PID接口编译失败，启用后通过。真实用户软件和完整系统权限未验，边界及日志见[本轮记录](../change-log.md#change-20261110-010)。

修订结果：真实CleanMyMac_5后台登录项未进入NSWorkspace运行应用列表，导致0.9.37无法生成退出预览。0.9.38补充解析目标包限定的lsof文本可执行文件，并以PID、启动时间、真实路径和文件身份复核。真实HealthMonitor已列出并完成正常退出，随后只回到卸载预览并取消；没有强制退出、没有移动应用包。结果见[20261110-011](../change-log.md#change-20261110-011)。
