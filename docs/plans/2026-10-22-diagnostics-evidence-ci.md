# MangoDisk 借鉴实施计划

日期：2026-10-22；基线 0.9.4。目标：保持现有删除边界，完成诊断、规则证据与 macOS 自动检查。

采用复用 Coverage 的最小方案；独立诊断服务／规则配置引擎虽然灵活，但当前无必要。KISS／DRY 复用扫描、确认及统一检查；SOLID 分开采集与展示；YAGNI 不扩大清理范围。

1. 固定原生包及签名，尝试读取原生控件；失败保留准确阻碍，不重置授权，不把 mock 当真机验收。
2. Coverage 增加默认空的有界诊断（最多 50 项，路径／原因／原始错误有长度上限），兼容旧数据。普通扫描与 AI 使用同一字段，路径仅显示在本地，不持久化 AI 报告。
3. 显示有界路径详情及原因，转义控制字符，不根据文字猜测权限；诊断阅读不得调用扫描／删除。限额、取消、链接、深度和并发变化分别编码。
4. npm／pip 复用 RuleEvidence，写明固定默认根、官方命令、恢复条件和官方资料；修正配置路径重定位后说明，不增加清理规则或更改执行参数。
5. macOS CI 安装锁定依赖，运行 npm run check、原生构建与完整签名验证。只读仓库权限，不上传应用或扫描数据。云端运行待提交后验证。
6. Rust 验证上限、旧字段兼容、错误与来源；浏览器模拟验证详情、旧字段、零额外 IPC 与窄窗口，运行统一检查；最终打包并核验签名、更新版本和日志。

M3 已尝试：0.9.4 包签名通过、原生窗口可定位；读取页面 AX 控件返回 AppleEvent -10000，故授权／拒绝／重启仍待实测。此阻碍不妨碍诊断和 CI 配置实施。不得为此自动操作授权开关。
