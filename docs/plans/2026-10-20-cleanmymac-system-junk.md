# CleanMyMac 系统垃圾模块深入逆向计划

范围：本机 CleanMyMac_5.app 5.7.2 的 SystemJunkScanning → 扫描核心 → 清理核心及特权调用边界。用户已同意模块深入路线；不以留白功能迭代代替逆向成果。留白保持 0.9.1。

方法选择：采用官方 Ghidra 独立本地安装，校验发布 SHA-256，通过 REA 6.7.0 获取函数、伪代码与引用。替代为 Hopper／IDA，当前未配置且可能需要额外许可，不优先采用。不运行第三方 setup、不安装全局代理技能、不修改登录或许可。

1. 固定目标和工具版本、目标哈希；记录环境和下载校验。
2. 让分析引擎就绪，优先导入 arm64 系统垃圾框架，保存数据库和分析限制。
3. 找到具体扫描任务、路径与过滤条件，至少深入一个函数的调用／条件关系，不将字符串列表当作规则还原。
4. 追踪清理入口与执行边界，区分任务生成、大小统计、删除／移到废纸篓及特权请求；没有调用证据的部分标未知。
5. 尝试读取目标自身的原生界面和扫描入口。若系统辅助功能／录屏未授权，不重置或代替用户授予，不把静态结果写成动态验证。
6. 仅在能明确指定临时样本范围并保证不触发真实数据清理时做动态扫描对照；否则保留样本计划与未验证项。不得因探索点击清理／优化按钮，不申请特权助手安装或许可绕过。
7. 输出函数证据、调用图、规则证据表与覆盖缺口；校验目标哈希、报告及日志，不升级或构建留白。

KISS：围绕单模块逐步扩大；YAGNI：不同时追杀毒与更新；SOLID：扫描、规则判断、清理执行和特权传输分别取证；DRY：统一证据编号与本地原始输出索引。结果必须区分直接反编译观察、调用关系推断和动态验证，不能宣称完全还原。

本轮结果：用户缓存核心链阶段取证完成，22 个选定函数／消息桩及 8 组受限目标类执行结果可复核。既有窗口仅观察，没有新扫描或改动用户选择。真实知识库规则、分类到清理器绑定和其他系统垃圾类别仍未还原，不能将整个计划范围标成完全完成。见 [深入报告](../cleanmymac-system-junk-re.md)。
