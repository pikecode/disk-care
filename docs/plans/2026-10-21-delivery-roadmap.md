## M1：结果页，首个实施工作包

涉及：修改 `src/App.tsx`、按需复用 `src/CleanupOutcome.tsx`、`src/style.css`；新建 `scripts/cleanup-results-ui-smoke.js`。沿用 `src/types.ts` 的 Outcome／Record；除非发现缺陷，不改后端执行策略。

1. 阅读所有结果展示、`startScan`、`clean`、`prepare_cleanup` 调用；确认旧历史缺少 status 时现有兼容逻辑。明确“失败／跳过”筛选不能依赖中文 message 猜测状态。
2. 按 `scripts/cleanup-trust-ui-smoke.js` 的 IPC fixture 约定新增用例：全部成功、混合失败／跳过、全失败、旧记录缺 status、空结果。记录点击查看／筛选时 IPC 调用次数，要求无新增清理请求。
3. 实现全部／失败／跳过结果筛选及数量，复用原逐项结果组件。旧数据只按确证字段分类，不能推测跳过；空结果不显示“全部成功”。
4. “查看剩余项目”仅导航到清单并提示结果已过期，不自动扫描、选择或执行。“重新扫描”才启动扫描；任何重试需新的扫描、预览、确认。
5. 构建并通过新增 smoke、既有 cleanup-trust 回归；记录键盘、窄窗口及重复点击行为。不得将 mock IPC 作为真实清理验收。
6. 更新进度／修改记录／验证；需要交付应用时统一更新版本、构建及签名核验，不提前承诺版本号。

执行检查：`npm run build`（类型及前端构建成功）；浏览器加载开发页面，按仓库约定执行新增及既有 smoke 函数，断言通过且无 pageerror。后端未改则不重跑无关 Rust 全量测试。

## M2 / A1：AI 数据只读账本

设计依据：[AI 工作数据专项设计](2026-10-21-ai-workspace-data-design.md)。新增 `src-tauri/src/ai_data.rs`、`src/AiData.tsx`、`scripts/ai-data-ui-smoke.js`；修改 `src-tauri/src/core.rs`、`src-tauri/src/lib.rs`、`src/types.ts`、`src/App.tsx`、`src/style.css`；Rust 单测放在新模块内，测试根由临时目录创建。

1. 建立最小兼容表：工具、实测版本、根目录来源、识别规则、依据、未覆盖项。无证据的规则先归未知，不把官方最新文档等同已安装版本。
2. 写 fixture 测试：未知版本、凭据／记忆保护、混合目录、链接越界、重复根及硬链接。先确认测试失败，再实现路径识别和分类纯函数；保护规则优先。
3. 写遍历测试：取消、预算、权限错误、文件消失、读正文被禁止。实现有界只读统计，复用 Coverage 和作业互斥，不能持有全部文件内容或递归无限目录。
4. 固定 Rust／TypeScript DTO：来源、类别、占用口径、覆盖、影响、策略、活动状态；未知值保持未知。只注册 `analyze_ai_data`，不新增删除 command 或扩充 Action 枚举。
5. 新增 UI：先选范围再分析；工具／类别／分组展开及分页，保护和未知明确标注，所有 AI 项无清理操作。首期根路径覆盖不全时提示用户补充。
6. 新增 IPC fixture：页面切换和筛选不能触发删除命令；无安装、无权限、超限、活动、错误、取消状态均可读。通过后再做用户已选根目录的只读实机验证。
7. 更新进度／规则来源与兼容表／版本记录。验收不足时明确标为“实现完成、实机待验”，不自动进入 A3。

检查命令：`cargo test --manifest-path src-tauri/Cargo.toml ai_data`；`npm run build`；浏览器执行 `scripts/ai-data-ui-smoke.js`。若修改共享 Engine，再运行 `npm test` 及现有清理／取消相关 smoke。文档中记录准确测试数和结果。

## M3：权限实机闭环

涉及：`docs/manual-permission-check.md`、`docs/verification.md`；只有复现确定根因后再改 `src/ScanAccess.tsx` 或后端路径处理，避免预设修复。

1. 固定应用构建，记录系统版本、应用位置、签名标识和可见权限状态，不主动重置 TCC。
2. 验证默认扫描、扩展扫描、用户选定 AI 根三条入口；覆盖拒绝、取消、已授权及重启。每项记录实际弹窗、覆盖状态与恢复办法。
3. 需要重置授权才能覆盖的场景另行明确请求，不把先前授权视为已覆盖所有测试。
4. 必要修复后只复测相关路径；`npm run verify:mac` 通过仅证明包校验，不等于系统已授权。
5. 如果受实机状态限制，保留阻碍和可复现步骤，可继续只读文档整理，但 M6 不能越过相关权限与安全门槛。

## 每轮执行和汇报

开始前读取本文、专项设计、`docs/progress.md` 及最新修改记录。默认继续最早未完成且未受阻的工作包；用户指定某项时记录调整原因，不默认回到无限纯逆向。实施中若需要研究，只追会阻塞当前验收的问题。

每轮交付必须有：工作包状态、实际修改文件、用户可感知变化、运行检查及未运行项、剩余阻碍、下一任务。更新 `docs/change-log.md` 和 `docs/verification.md`；总进度只维护当前状态。提交／推送和打包按用户授权与交付范围执行，不自动夹带此前未提交研究。

KISS 小步完成一个流程，DRY 复用已有组件／安全校验，SOLID 分离只读分析和删除，YAGNI 推迟正文分析、自动重试、定时清理和全量插件框架。实施时按变更范围运行相关构建与测试，保留已有工作区修改。
