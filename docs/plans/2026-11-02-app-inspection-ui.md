# 应用残留检查桌面交互调整

用户反馈：列表之后仍是长篇说明和表单，缺乏专业应用的视觉层级。本轮只调整该页面，保留现有范围与后端检查契约。

## 方案与取舍

1. 推荐左右分栏：左侧搜索、应用列表、行尾检查；右侧应用身份、三类范围和报告。适合连续检查多个应用，选择后不滚动跳转。
2. 列表配确认弹窗：首屏更简洁，但连续检查需反复开关弹窗，结果仍需另设区域，本轮不采用。

KISS：复用现有状态和检查入口。DRY：复用 CoverageDiagnostics、格式化和图标依赖。SOLID：仅调整呈现层，不更改检查／删除边界。YAGNI：不增加图标抓取、批量扫描或自定义规则系统。

## 布局与状态

- 延续米白与绿色，主标题保持应用既有字体；控件采用系统无衬线，字号 11／12／13／16／20px，间距以 4px 为基准。
- 列表用名称首字作为占位标记，不伪装成真实应用图标。名称与应用标识截断，悬停完整名称和路径，选中后右侧展示路径。
- 初始空态提供载入应用；读取中显示状态与停止，失败保留可恢复入口，搜索无结果单独提示。
- 行尾“检查”选择目标并把键盘焦点交给右侧；确认后启动，选中本身不扫描。
- 范围以缓存、应用数据、偏好设置三行展示，个人资料／敏感配置直接可见；精确路径和预算按需展开。保留只读确认门槛。
- 最近报告独立标出目标，不能把上一个报告冒充当前选择的结果。覆盖状态及敏感内容说明保持可查。
- 960px 双栏无横向溢出；更窄时上下排列。列表独立滚动，长列表不把操作区推离屏幕。

## 验收

前端构建；浏览器模拟多应用、长名称、搜索、焦点、确认、不同来源状态、列表失败／取消、候选定位失败和零删除调用。查看列表与详情截图。真实 macOS 权限、真实扫描与系统图标不在本轮验收结论内。
