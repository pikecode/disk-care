# 模型账本可靠性与展示完善

目标：修复宽目录扫描的文件句柄积压，让不完整状态在折叠时可见，并限制文件块详情的界面渲染量。沿用 brainstorming 的方案梳理、writing-plans 的实施步骤和 ponytail 的最小变更原则。

方案一（采用）：路径队列 + 固定仓库目录描述符逐级打开；无需改变进程资源限额，保留每级禁止链接。方案二：限制待扫描句柄队列；改动更少但会降低有效覆盖率，不采用。测试只在独立子进程降低额度，避免影响并行测试和应用。

1. model_storage.rs 新增 64 句柄额度、200 模型宽目录的子进程回归；先确认现有实现失败。
2. 队列只保留相对名称，每次从固定清单根逐级 openat + O_NOFOLLOW；不回退到绝对路径打开。补充根目录替换／中间链接拒绝断言，验证安全边界。
3. ModelStorage.tsx 折叠摘要直接区分部分与已停止，文件块详情展开时才渲染，每次显示 50 条。搜索、模型分页、引用跳转及旧数据兼容保持。
4. 扩展 model-storage-ui-smoke.js，验证未展开时无文件块条目、展开 50 项、继续加载以及折叠不完整状态；执行相关项目／关系图回归。
5. Rust 全部自动测试、Clippy、生产构建和默认仓库只读检查；升级 0.9.1，原生打包及完整签名验证，保留 0.9.0 并更新文档和日志。

KISS：沿用现有扫描和组件，未增加服务；YAGNI：不扩展仓库及删除；SOLID：文件打开与遍历职责分明；DRY：安全相对打开集中到一个辅助函数，界面复用已有数据。不以提高系统额度掩盖资源问题。

不改变实际扫描限额、不自动授权；真实系统弹窗仍需单独验收。工作目录无 Git 元数据，不创建提交或 worktree。
