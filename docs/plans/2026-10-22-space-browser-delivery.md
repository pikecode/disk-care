# 空间管理首批实施计划

日期：2026-10-22。基线 0.9.5。用户授权规划并实施推荐路线；本轮交付范围为原生权限补验尝试、普通目录空间地图与只读大文件清单。

## 目标与取舍

推荐扩展现有目录浏览，复用当前扫描 ID、允许根、路径校验、目录缓存、分页、取消和矩形布局。备选为新建独立扫描入口／引擎，能更自由选择目录，但增加权限与重复扫描风险，暂不采用。

首版从扩展扫描主要目录或现有清单“浏览目录”进入，逐层浏览其普通目录；不增加任意根扫描。地图最多 30 个最大正占用子项，其余合并“其他”；数据来自整个当前层缓存而非已加载分页。小项可回到现有列表，零占用不绘制面积。

大文件来自同一次元数据遍历，不读文件正文。每目录缓存保留当前子树最大的 100 个逻辑大小至少 1 MiB 的普通文件（根内硬链接身份去重），记录逻辑大小、分配块、修改时间；全部候选数另记。界面过滤仅作用于保留清单，明确可能还有匹配项。提供名称／类型／最小大小／修改时间筛选和 Finder 定位，修改时间不代表最后使用，分配块不代表可回收量。

没有删除、废纸篓、哈希比较、自动选择或模型移除。仍跳过链接、跨卷及既有私有数据边界；预算、超限和覆盖状态不放宽。缓存时间及目录完整性继续按既有规则，部分结果不拼接分页，不宣称完整排行。

## S1：原生权限补验

固定包版本、签名与进程；仅尝试读取目标窗口和控件，禁止改变或重置系统授权。已有控件树 -10000 记录不能写成修复。能交互时逐项验证确认前不扫描、取消、拒绝和重启；受环境限制时保留阻碍，同时推进独立只读功能，不开放后续删除规则。

## S2：后端有界元数据

文件：`src-tauri/src/core.rs`、`src-tauri/src/lib.rs`。

1. 先写合成目录断言，覆盖全层地图面积聚合不受 200 项分页影响、大小排序、最大发电100项、硬链接／符号链接、稀疏文件、取消和隐私边界。
2. 在现有 measure_directory 遍历中以固定容量最小堆保留大文件；不再单独遍历。Listing 增加可选地图数据、大文件、计数与 Coverage；旧前端忽略新增字段。
3. Finder 定位只接受当前根 ID、相对路径和观测时间，从未过期缓存核对确实出现过的文件，重新检查边界、类型和文件身份，再调用固定 `/usr/bin/open -R`。错误及过期均停止，不把前端路径作为新授权。
4. 测试过期、越界、链接替换、未知文件均拒绝；测试不打开 Finder。

## S3：前端只读浏览

文件：`src/types.ts`、`src/api.ts`、`src/App.tsx`、`src/DirectoryInsights.tsx`、`src/spaceLayout.ts`、样式。

1. 目录对话框保留默认列表，增加地图／大文件切换与逐层面包屑。
2. 地图复用 layoutSpaces，顶层聚合覆盖所有正观测子项；点击目录沿既有入口读取下层，点文件仅查看，不自动定位。列表与图形键盘可用，面积不加最小值失真。
3. 大文件过滤／分页均本地处理；Finder 定位只在明确点击时触发后端，旧 Listing 无字段时解释暂不支持，不显示错误零结论。
4. 不新增主导航和重复扫描流程，不改变清理选择／预览逻辑。

## S4：验收与交付

新增 `scripts/directory-browser-ui-smoke.js`，合成 IPC 验证入口、地图与聚合、面包屑、筛选、部分／空／旧报告、零自动扫描与删除、Finder 仅显式调用、键盘和 960px。运行后端测试、npm run check 与受影响旧 UI 回归；真实权限另记。

构建新版本、验证完整签名，旧包留回退；同步 README、进度、验证、产品设计、记录及统一路线图。未提交不宣称云端 CI 通过。

## 验收标准与工程原则

用户能从当前扫描结果找大目录、逐层进入并查看大文件及 Finder 位置；全程只读、有界、覆盖可解释。KISS／DRY 复用遍历、分页和布局；SOLID 分开采集与展示；YAGNI 延后通用删除和独立引擎。原生权限失败时保留待验，不以模拟结果替代。
