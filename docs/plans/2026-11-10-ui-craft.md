# 桌面视觉与交互细节打磨

用户要求：现有界面粗糙，缺少专业软件的层级和细节。先归档0.9.35已验证功能，再以0.9.36独立完善视觉，不扩大清理范围。

选择：局部更换配色成本低但不能形成一致性；采用公共控件规范＋应用管理样板，后续复用。KISS减少重复卡片与技术信息；DRY直接调整现有选择器而不层叠另一套主题；SOLID保持视觉与执行保护分离；YAGNI不增加主题配置或动画框架。

## 标准

- 系统无衬线字体；页面标题26、详情20、正文13、辅助11～12。移除宋体页面标题和倾斜品牌装饰，数字等宽。
- 间距4／8／12／16／24／32；主按钮36高、图标按钮28～32；圆角6／8／12。中性画布与白色表面，绿色用于主操作／当前状态，危险动作独立提示色。
- 统一hover、active、focus-visible、disabled；键盘与可访问名称保持。仅在列表悬停／当前／焦点状态加强次要操作，但不能造成不可达操作。

## 文件与行为

1. `src/style.css`直接调整字体、侧栏、标题栏、按钮、焦点与应用区域，不新叠加整套覆盖层。应用列表和详情使用独立滚动，最低960×660保留主操作；小于桌面宽度时退回自然布局。
2. `AppResidue.tsx`整行主按钮选择，名称／版本／保护标签分层，次要卸载使用具名图标按钮；详情将位置标识折叠，检查与卸载对齐；选择新项时详情回顶部，报告逻辑及确认不变。
3. `AppIcon.tsx`无系统图标时使用统一应用图形，避免随机大字占位；真实PNG加载逻辑不变。`App.tsx`简化重复工作空间文字、隐私和版本状态，不伪造权限。
4. 核心七组及项目／地图／AI／开发工具四组回归，统一入口扩为十一组，补验长名称、独立滚动、选中新项回顶、最低窗口、焦点和弹窗。人工逐张检查截图，发现问题继续修正；全量检查、构建与完整签名后本地交付0.9.36，保留0.9.35，按Git规则提交和标签，不自动推送。

本轮不宣称全产品视觉或首次用户可用性已完成；原生权限、结构化失败原因仍单列。

进度：已有系统字体／公共控件与应用管理样板、独立滚动及选中状态细节；核心七组和额外四组均通过后，统一入口固定扩为十一组。最终结果与原生边界以[本轮记录](../change-log.md#change-20261110-008)为准。

## 桌面结构修订（2026-11-10）

用户明确指出第一版仍像网页，原字体／颜色样板不作为最终结构验收。推荐沿用 Tauri 的原生窗口装饰与菜单：相比 SwiftUI 全量重写，保留现有受控功能且减少迁移风险；相比继续修改卡片样式，直接移除网页式重复标题和外层卡片。

- 保留真实红黄绿，Overlay 标题栏并隐藏系统标题，工具栏背景可拖动；不模拟窗口按钮。窗口权限仅拖动和双击缩放。
- 侧栏固定导航，顶部单一紧凑工具栏；移除页面大标题和重复说明。应用管理占满内容区域，列表和详情独立滚动，搜索／刷新归入工具栏。
- 应用右键及 Shift+F10 使用系统菜单；查看不扫描，检查需明确命令，卸载仅进入原预览确认。菜单仅开放创建／弹出／释放资源权限，不增加文件访问或删除能力。
- 十一组模拟回归之外，原生包还需验证窗口按钮、工具栏、最低尺寸与合成应用只读检查；先前网页结构原生结果不能替代本次验收。

依据：[Tauri 原生窗口定制](https://v2.tauri.app/learn/window-customization/)，实际字段及菜单生命周期核对已安装版本配置 schema 与 TypeScript 声明。
