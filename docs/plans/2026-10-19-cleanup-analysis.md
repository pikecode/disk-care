# 可清理空间分析实施计划

> 按用户纠正执行：先分析实际数据，说明能否处理及影响，再由用户选择；撤销未发布的目标空间输入。本轮不增加删除范围。

**目标：** 交付 0.6.0 扫描结果分类面板，统一手动和单项预览的资格判定。

**架构：** TypeScript 纯函数按合格、受阻、只读、零观测分类；React 显示观测占用、阻止原因、恢复影响；App 复用后端预览与执行，不修改 Rust 接口。

**技术栈：** 现有 React、TypeScript、CSS 和 Tauri；无新增依赖。

## 实施步骤

1. 移除未发布的目标组件、组合算法及目标结果状态；更新产品设计与撤销说明。
2. 新增 `src/cleanupEligibility.ts` 和 `scripts/cleanup-analysis-check.ts`，核验重复/非法/不完整/阻止/只读/零占用分类及合计。
3. 新增 `src/CleanupAnalysis.tsx`，显示实际合格范围，不自动勾选，逐项说明恢复影响和预览入口。
4. `src/App.tsx` 的清单选择与分析复用资格，预览调用复用原令牌、确认与执行流程。
5. 新增模拟 IPC 界面检查，验证默认无选择、阻碍依据、只读数据不计入、预览/取消/确认、过期和无候选；原缓存清理界面回归。
6. 运行数据断言和生产构建，构建 0.6.0 app，备份旧版并核验启动，回填验证记录并清除编译中间文件。
