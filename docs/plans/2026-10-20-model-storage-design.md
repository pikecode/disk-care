# 模型空间账本设计

日期：2026-10-20。依据：[定点研究](../cleanmymac-static-analysis.md)。本方案已于同日实施为 0.9.0，实际边界与验证见 [20261020-004](../change-log.md#change-20261020-004)；以下保留设计与取舍。

## 目标与方案

用户需要知道模型占用来自哪里、哪些文件共享、哪些项目存在引用，不能把所有模型都列成垃圾。现有模型名称与项目引用关系保留。

方案一（推荐）：新增只读模型账本，解析有界清单，建立模型到文件块的关系，展示独占与共享占用。可解释、复用现有项目证据，改动集中。

方案二：先接入模型管理工具列出其报告大小。开发较快，但工具显示大小不能直接说明共享文件的磁盘占用；外部工具缺失或自定义服务地址也需要处理。仅适合辅助核对，不能直接当作可释放量。

暂不提供模型删除，不安装分析引擎，不增加常驻服务。此处不推测或复制同类产品算法。

## 数据与边界

- 模型存储根使用现有已知默认目录；自定义根暂不支持并明确标注，不能把默认目录为空写成没有模型。
- 有界读取 manifest，校验 JSON 类型、摘要格式、大小及条目数量；摘要只能映射到根内固定 blobs 文件名，拒绝路径片段。
- 延续 checked_path／checked_read_path、O_NOFOLLOW 和截止时间规则；目录链、文件读取及元数据均需遵守既有私有路径和链接边界。
- 模型与块之间按摘要去重；每个模型同一摘要只计一次。共享引用以本次完整读取的清单为范围，不代表全系统使用关系。
- 展示文件逻辑大小与分配空间的区别；缺失文件、清单解析失败、超限或取消都使关联结论不完整。部分结果不得承诺独占或可释放。
- 共享文件只能在全库去重总占用中计一次；单模型的关联总占用不能跨模型相加。APFS 克隆、硬链接造成的物理共享仍需明确测量限制。

## 架构与展示

Rust 增加独立只读分析模块，输出模型、块引用、观测字节及完整性；复用当前安全读取和取消模式，不混入清理执行模块。需要扫描进度和时间上限，不能阻塞界面。

界面复用项目账本与关系图入口：模型显示关联占用、共享占用及独占候选占用；未测量或不完整时显示原因。项目配置引用以原有结构化证据关联，不能把没有引用或没有进程解释为未使用。全库去重占用独立展示，不称可回收空间。

错误分类区分不存在、不可访问、链接拒绝、无效清单、缺块及超限。只记录必要路径与原因，不保存清单全文或配置正文。没有新增删除命令、清理按钮或权限探测。

## 验收与实施顺序

1. 先实现临时目录测试：两个模型共享块、重复摘要、缺失块、坏 JSON、摘要路径穿越、末级及父级符号链接、超限、取消和未完整清单。
2. 实现只读汇总：完整样本中总量去重；共享计数准确；部分扫描不作独占保证；声明大小不代替文件测量。
3. 对接数据类型、现有项目名称关联及界面；验证共享数值不可相加、不显示可回收量、部分数据明确提示，旧报告兼容。
4. 运行针对性 Rust 检查与界面模拟，最后做真实默认目录只读验收；交付时完整签名验证并更新日志与版本。

KISS：单一只读链路，不增加后台；YAGNI：暂不扩展其他模型仓库和删除；SOLID：解析、归属统计与执行分离；DRY：复用现有路径保护及结构化引用。若为此重写通用文件索引器或所有图表会扩大范围，应避免。

实施结果：复用项目任务锁、取消标志及进度通道；独立模型完整性不混入项目产物基线。保留既有路径边界，并使用逐级 openat + O_NOFOLLOW 固定读取位置，按设备号与 inode 合并硬链接；有未归属硬链接时隐藏独占结论。模型限额为 5 秒、1,024 个条目、512 个模型、8,192 次引用、单清单 1 MiB／累计 8 MiB。真实大型清单促使初始 64 KiB／256 层限制调整为 1 MiB／4,096 层；测试证据见 [验证记录](../verification.md)。

后续可靠性修复：0.9.1 将目录句柄队列改为相对路径队列，由固定根逐级禁止链接打开；文件块详情按需分页。设计范围与既有限额保持，见 [修复计划](2026-10-20-model-ledger-hardening.md)。
