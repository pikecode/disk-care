# 核心交互验证接入CI

目标：固定0.9.34原生补验来源记录，并将已有七组核心模拟变成一条可重复命令。P1结构化错误另行实施，本轮不加入新产品功能或删除规则。

方案一逐个使用CLI手动执行，成本低但容易遗漏；采用方案二：锁定Playwright开发依赖、复用现有页面函数及生产构建，新增统一Node运行器，不改成另一套测试框架。KISS／DRY保持一个固定清单与原脚本；SOLID区分检查运行器、产品代码及原生验收；YAGNI不引入云测试平台或多浏览器矩阵。

1. `scripts/check-ui.mjs`：构建生产资源、启动独立preview且1420端口必须空闲、启动无头Chromium，每组独立上下文；固定执行导航、范围、结果、历史、活动、应用、卸载七组，只模拟IPC，不接入用户浏览器或系统权限。
2. 每组失败保存模拟截图／trace，所有结果保存JSON，任一失败退出非零；服务只清理自身进程组，不占用或终止用户已有服务。`package.json`提供`npm run check:ui`，Playwright只作为固定版本开发依赖。
3. 现有macOS工作流增加浏览器安装、核心模拟与证据保留；只上传UI模拟目录，7天留存，不上传其他output下的真实扫描／原生资料。新增artifact action版本从官方GitHub发布核对。
4. 安装时审计发现原有Vite6.4.4的中等级公告，使用同主版本6.4.6补丁修复；记录审计结果，不运行跨主版本自动修复。
5. 本地验证依赖锁、七组统一运行器、端口冲突失败及资源清理、原统一检查；配置／测试变更不升级应用版本或重建固定原生包。远端工作流只有用户授权推送后才能实际验证，本轮不自动推送。

原生补验使用独立0.9.34实例，现有PID74511不操作。验证冷启动无请求、范围取消、一次常规只读扫描保存入口／版本／会话／结束，面板读取、空闲正常退出与重新启动后记录保留／会话区分。不能把此结果解释为系统允许／拒绝或首次用户验收，也不反推旧0.9.32未记录的扫描来源。
