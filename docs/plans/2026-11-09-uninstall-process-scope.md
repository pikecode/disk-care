# 卸载进程检查范围修复

## 问题与选择

旧逻辑枚举全机 PID，再逐个读取可执行路径；一个无关但仍存活的进程返回 ENOENT 即阻断所有应用卸载。Codex 只是此次触发案例，不应增加软件名称白名单，也不能直接忽略所有查询错误。

方案一（采用）：保留 NSRunningApplication 的应用标识检查，使用系统 lsof 对所选应用包的文件引用做只读查询。方案二：保留全机进程扫描，为每个读取失败的进程建立可靠归属补证；实现复杂、扩大读取范围，暂不采用。按 KISS／YAGNI 使用系统能力、不增加依赖；按 DRY 复用命令超时及输出限制；运行状态检查继续由卸载模块负责。

## 行为与边界

预览与执行前都检查，固定参数 `/usr/sbin/lsof -nP -F p +D <应用包>`，不读取进程参数或环境，不终止任何已有进程。仅退出码 1、标准输出与错误输出均为空时确认无占用；存在引用则拒绝，警告、异常状态、启动失败、超时均拒绝。当前 macOS lsof 即使输出匹配引用也可能返回 1，不能只靠退出码判定无占用。无需解析 PID／文件描述符即可安全拒绝。

沿用五秒时限及有界输出；很大的应用包可能超时而无法卸载。文件引用检查可能因其他程序打开应用包内文件而保守阻止卸载；它与应用标识检查共同工作，不承诺识别所有应用包外的独立服务。检查存在瞬时竞态，不能保证检查后没有新进程启动。原应用身份、单次令牌、锁、废纸篓及关联资料保留机制不变。

共享命令执行器仅拆出退出状态、标准输出、错误输出，原清理命令包装保留错误状态检查、进程组超时终止及输出限制。

## 验证范围

全量检查包括构建、前端断言、Rust、格式、Clippy；专项新增无占用／警告／异常／有引用判断，并在原生测试内验证目标辅助进程阻断预览与执行、无关已删除可执行文件的存活进程不阻断。废纸篓往返仅操作测试生成的临时应用及缓存，恢复后由测试夹具清理；不卸载用户软件。最终结果见[本轮记录](../change-log.md#change-20261109-002)。
