# 清理依据与结果核验实施计划

**目标**：以 uv 默认缓存为首个完整样板，连接识别依据、恢复影响、目录保护、变化复核与执行后核验；完善所有扫描目标的覆盖状态和所有清理项目的执行状态。

**架构**：沿用 Rust Engine、Item／Plan／Record 和现有 React 清单。新增可选证据和覆盖字段保持历史数据兼容；内部保存 uv 元数据摘要，扫描、预览与执行前核对；用户保护按整个缓存根目录生效并持久化，不向官方命令虚构子目录排除参数。

**技术栈**：Rust 标准库、Serde、Tauri 2、React／TypeScript，不新增依赖。应用升级 0.9.2，保留 0.9.1。

## 方案与边界

采用：一类缓存完整闭环，复用已有执行通道。替代：同时扩充各类系统／应用垃圾；覆盖面更广但恢复与验证成本高，暂缓。uv 证据来自本项目独立定义的固定规则和工具路径查询，不使用逆向所得代码或未恢复的 CleanMyMac 规则。

元数据摘要识别观测范围内的变化，不能提供全局文件系统事务，也不能证明没有其他程序在使用文件。执行前仍检查配置、进程和安全路径；不自动终止进程。保护仅禁止清理，允许只读分析，保留错误时默认阻止的行为。不清理用户真实缓存，测试仅操作自有临时夹具。

## 实施步骤

1. 在 `src-tauri/src/core.rs` 补覆盖状态与计数，保留因取消未访问的目标；区分不存在、主动跳过、权限拒绝、其他失败、上限和取消。读取错误不再通过 exists() 当作不存在。
2. uv Item 增加规则编号／版本、识别来源、范围和恢复条件；结构化证据由后端产生。扫描及预览保留元数据摘要，变化或统计不完整时拒绝执行。
3. 添加 uv 根目录保护的后端读写和 Tauri 命令；持久化路径受现有安全检查约束，保护变更使计划失效。React 清单展示解释与保护操作，明确整目录范围。
4. Outcome 增加兼容旧记录的状态和清理前后观测；失败后剩余项目标记跳过。执行后重新测量，测量失败不伪装成命令失败。磁盘可用空间显示有符号变化，不归因给单个命令；旧 released 字段仅兼容保存。
5. 增加变化、保护、覆盖与旧记录兼容的 Rust 断言；用临时 uv 样本核对真实官方命令，不执行用户缓存。增加界面脚本验证新解释、保护、状态和负空间变化，回归既有清理流程。
6. 执行 Rust 测试、格式／Clippy、前端构建及相关界面检查；打包 0.9.2 并验证完整签名，保留旧版，更新 README、设计、验证和修改记录。

KISS：沿用三个数据模型和已有清单；YAGNI：先覆盖 uv，不做通用规则编辑器或后台清理；SOLID：规则依据、资格检查、执行结果各司其职；DRY：统一覆盖字段和执行状态呈现，复用安全路径与官方命令逻辑。

仓库无 Git 元数据，不创建提交或 worktree。系统授权弹窗仍需独立实机确认，不把模拟 IPC 当作系统权限验收。
