# AI 工作数据账本设计

日期：2026-10-21。状态：设计已记录，尚未实现。适用工具首批为 Codex CLI、Claude Code；桌面端、IDE 扩展、云端数据不自动视为同一目录结构。

## 产品价值与方案

回答四个问题：数据占在哪里、属于哪个工具／目录分组、为何增长、处理后失去什么。复用留白的项目与依赖感知定位，增加 AI 工作数据视角，不把文件夹占用换个名字叫垃圾。

| 路线 | 优点 | 局限 | 决策 |
| --- | --- | --- | --- |
| 规则加文件元数据，先只读 | 可解释、离线、无需读取对话正文，容易验证 | 首期不能准确关联所有项目／会话 | 推荐，首期实施 |
| 解析全部对话并调用模型判断价值 | 能识别语义及重复内容 | 隐私、成本、提示注入和误判；“没价值”无法可靠证明 | 不进入首期，也不以模型判断授权删除 |
| 整目录按天数清理 | 实现简单 | 混入配置、记忆、恢复资料；时间不能证明安全 | 不采用 |

核心差异应是“清理影响与可核查证据”，而非宣称能够自动判断所有 AI 记录有没有价值。

## 已核实资料与版本边界

资料核对日期为 2026-10-21；本机仅查询到 Codex CLI 0.163.0，未验证 Claude Code 版本或实际数据格式。未读取用户对话、凭据或配置正文，未扫描用户目录占用。

- Codex 状态根目录由 `CODEX_HOME` 决定，默认 `~/.codex`，其中混有配置、认证、历史及其他状态。`history.max_bytes` 可控制历史文件大小，但不能据此说它控制所有会话文件。[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-advanced)
- Codex 的日志目录可由 `log_dir` 修改，默认位于状态根下；仅扫描默认路径可能遗漏数据。[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)
- Claude Code 的数据根可由 `CLAUDE_CONFIG_DIR` 改变。项目目录包含会话资料，部分文件有自身保留规则；官方项目 purge 会连同自动记忆一起清除，不能作为“清缓存”按钮。[官方目录说明](https://code.claude.com/docs/en/claude-directory)
- Claude 的编辑快照用于恢复检查点，删掉后可能无法回退，不是无后果的缓存。[官方检查点说明](https://code.claude.com/docs/en/checkpointing)
- Claude 自动记忆可能位于 `projects/<project>/memory/`，与会话同处项目数据树，但保留规则不同。[官方记忆说明](https://code.claude.com/docs/en/memory)

以上是来源事实；以下是留白的保守产品策略，并不等于工具官方保证可删除。目录与格式会随版本变化，未验证版本只做结构统计，不能开放清理。安装版本与文档不同之处必须留在兼容矩阵中。

## 哪些能处理，哪些应保留

| 数据类型 | 有价值的分析 | 首期策略 | 将来允许处理的条件／影响 |
| --- | --- | --- | --- |
| 明确可重建的下载／展示缓存 | 占用、增长、重建来源 | 候选，仍只读 | 逐规则证明用途、可再获取、没有唯一用户修改，工具退出后重新核验；可能需要联网 |
| 诊断日志 | 文件数、年龄区间、大文件排行 | 候选，仍只读 | 用户不需排障、非活动写入、有保留策略且影响明确后处理；失去排障记录 |
| 会话、提示历史、工具输出与附件 | 目录分组、占用、时间分布 | 需用户审阅，不自动选中 | 视为用户记录，按会话依赖整体规划；删除可能失去继续会话、检索及附件引用 |
| 编辑快照、恢复资料 | 占用与恢复关联是否已确认 | 默认保留 | 不独立删除仍被保留会话使用的快照；必须单列放弃恢复能力的确认 |
| 长期记忆、技能、代理定义、规则、计划文档 | 数量、占用、所属工具 | 默认保护 | 不加入通用清理；用户明确整理是另一种任务，不能按老旧程度自动删除 |
| 认证、配置、MCP 设置 | 仅必要的存在／元数据检查 | 保护，不读取正文 | 不纳入清理白名单，不输出密钥或配置内容 |
| SQLite、WAL、SHM、索引、锁及后台状态 | 单独标为活动状态或未知 | 保护 | 不按后缀删除；数据库维护只能通过已验证的工具原生机制 |
| 工作树、未提交代码、用户输出文件 | 路径及潜在项目归属 | 保护 | 不因工作树“旧”、路径失联或缺少引用就删除；先核实 Git 与唯一文件 |
| 未识别目录 | 大小、文件数量及覆盖缺口 | 未知，仅分析 | 缺证据即保留，不根据目录名含 cache 就开放删除 |

`cache`、`tmp`、`archive`、`backup` 这些名字、mtime 过旧以及本机没有进程，都不能单独证明安全。活跃进程识别失败时标为未知；后台会话也必须纳入，锁文件不能被拿来清掉以“解除阻止”。

## 首期交互与范围

入口为“AI 工作数据”，与当前空间清单并列。默认不自动扫描，进入后明确展示待检查工具和根目录，用户点击“开始只读分析”。不增加启动时的全盘扫描，也不递归其他应用私有容器。

结果按工具 → 数据类别 → 目录分组展开：显示观测占用、文件数量、最近修改时间、覆盖状态、分类依据、处理影响。四种处理策略为“可重建候选”“需审阅记录”“保护”“未知”，另用独立字段说明本轮是否完整，避免把未知大小显示为零。

首期所有条目都没有删除能力。顶部显示“已观测占用”，不显示“可释放 X GB”；候选只代表值得核验。单独提供“查看依据”和“查看位置”。历史／快照不默认勾选，保护项不出现清理按钮。真正可执行规则仍只有已有的 uv/npm/pip。

目录名不可靠地反解成真实项目路径；首期只称目录分组。未核实关联标为未知，不画确定的依赖连线。项目／会话关联与增长基线属于后续 A2，不在首期伪造。生成代码和构建产物继续由既有项目账本分析，没有证据就不归因于某个 AI 工具。

## 扫描边界与数据模型

新建 `src-tauri/src/ai_data.rs`，通过现有 Engine 作业互斥与取消机制暴露 `analyze_ai_data`。前端新建 `src/AiData.tsx`，DTO 放入 `src/types.ts`。复用 Coverage、路径校验、大小格式化及显示组件；不得为独立页面再造通用扫描框架或删除引擎。

首期 DTO 最小字段：工具标识、根目录与来源、测量时间、覆盖状态、项目列表。每项包括规则 ID／规则版本、相对路径、类别、逻辑字节、分配块字节、文件数、最近修改时间、处理策略、依据、影响、活动状态。字节未知使用空值而非 0，`cleanupEligible` 恒为 false。不得向 IPC 返回对话正文、token、完整配置或进程环境变量。

路径发现优先使用用户确认的根目录，兼容默认位置；环境覆盖只接受可见且经过路径校验的值，不读取其他进程环境。GUI 无法获取终端的环境时显示“尚未验证其他位置”，允许用户指定，不谎称发现了全部安装。日志等自定义路径首期由用户明确添加，暂不解析完整配置文件。

只读 `symlink_metadata/lstat`，不跟随符号链接；逐级校验根及子路径、文件身份、类型与边界，扫描中变化记为不完整。默认预算：每工具最多 100,000 个条目、深度 12、30 秒；总预算 60 秒，采用迭代遍历，支持取消。超限、权限不足、路径消失均部分返回，保留问题数量；不得为做统计触发授权循环或提权。

同一根内按设备号和 inode 去重硬链接；不同根重叠先排除重复根，跨根物理共享无法核实时不提供物理总量。逻辑大小与分配块占用并列说明；APFS 克隆和快照使分配块不等于独占／可回收空间。父项和子项不得重复相加。

首期报告仅存内存。分类采用版本化规则和明确来源，静态路径仅是识别线索；未验证的内部目录归未知。根路径含用户信息，不默认进入遥测、Git 或测试截图。

## 后续阶段

- A1：只读目录与类别账本，保护规则、覆盖状态、解释和 fixture 测试。无历史正文解析，无文件删除。
- A2：经用户选择范围后，按已验证格式读取有限结构元数据建立项目／会话关联，并保存用户可清除的基线。必须限制读取字节和行数，不加载消息文本；活动、损坏、未知格式降级。增长只对同范围且完整的两次观测计算，时间显示为修改时间而非“最后使用”。
- A3：仅为证据完备的可重建缓存／日志新增执行规则；每个规则独立审核，计划过期、路径变更、工具重启均须重新核验。会话归档和放弃恢复能力为后续独立设计，不与缓存合并授权。

如果没有满足 A3 条件的规则，可执行空间就是零，也允许只交付有价值的诊断。归档同一卷不能宣称释放空间；删除也不等于安全擦除隐私数据。

## 验收用例

必须使用合成 fixture，不使用真实对话或认证文件：

1. 同一根混合缓存、历史、记忆和凭据：保护项永不进入候选；不打开文件正文。
2. `projects/<id>/memory/` 嵌套在会话树中：优先应用保护规则，禁止父级覆盖保护。
3. 自定义根、未知版本、目录缺失、链接到根外、重复根、硬链接：边界正确，统计不重复，未知不变成可清理。
4. 目录遍历遭拒、遍历期间变更、超过预算和取消：返回部分状态，不显示完整／零占用。
5. 活跃或无法确定活动状态：显示阻止原因，无操作按钮。
6. 页面纯展示和筛选不调用 `prepare_cleanup`／`execute_cleanup`；旧缓存清理行为不改变。
7. 窄窗口、键盘展开与筛选、空报告及大量条目分页通过；状态不能仅靠颜色辨认。

真实只读验收在用户确认工具根目录后进行；权限拒绝也是验收结果。A1 不以真实删除作为测试。实施步骤见 [统一执行计划](2026-10-21-delivery-roadmap.md)。
