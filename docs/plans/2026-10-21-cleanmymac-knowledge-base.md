# CleanMyMac 知识库执行链深入研究

目标：补齐上一轮真实知识库实现缺口，追踪缓存 isIgnoreItem／shouldPerformDeepSearchForItem 的真实调用与数据来源。留白保持 0.9.1。

推荐方案：静态定位真实实现、读取链和查询条件，再在独立进程用自有内存／临时数据库验证原对象。替代方案：只观察运行中的实际扫描结果；容易混入用户选择与既有配置，难以解释规则来源，不作为主证据。不运行真实清理或修改用户知识库。

1. 核验版本和研究目标哈希，定位实际实现所在模块，不按框架名称猜测归属。
2. 复用本地 Ghidra 项目导出查询、正则／精确匹配、默认／自定义合并及初始化代码；记录调用地址、分支与未解析项。
3. 仅在能指定自有数据库／资源时执行真实知识库对象；拒绝写入安装包、用户知识库或授权／许可数据。不把替身回调测试当成真实规则验证。
4. 如果包内知识库格式仍不清楚，记录已确认的加载、参数和查询边界，不凭数据魔数宣称已解密或得到规则全表。
5. 输出执行链、规则匹配语义、受控测试与覆盖缺口；校验哈希、文档和日志。本轮不实现新清理功能或重新构建留白。

KISS：复用现有引擎和导出脚本；YAGNI：不扩展到激活／许可或其他清理类别；SOLID：数据读取、匹配、扫描调用分别取证；DRY：统一真实实现与样本证据索引。
