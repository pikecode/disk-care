# 留白：项目与依赖感知的空间管理

日期：2026-10-19。状态：设计确定，按阶段交付；实现状态以实施计划和验证记录为准。

## 定位与目标

面向 macOS 开发者和本地 AI 用户，回答“空间属于谁、处理影响谁、空间为何再次增长”。现有版本已有主要目录分析、15 类规则、uv/npm/pip 官方命令清理、进程检查、确认令牌与结果核验；继续使用 Rust + Tauri + React，不引入后台服务或云端分析。

## 用户流程

1. 输入主目录内的工作目录，显式启动扫描。
2. 自动识别 Node、Rust、Python 项目；按项目展示已识别产物占用，而非冒充项目全部大小。
3. 展示进程路径、配置中本地模型名称引用、重建条件、检测盲区。
4. 与同一工作目录上次完整扫描比较，区分新增、消失和已测量占用变化。
5. 跳转现有缓存清理流程，预览、确认、执行、核验可用空间；项目产物删除按第二阶段单独上线。

## 阶段与验收

### 分析分类与处理建议：0.7.0（已交付）

延续“扫描事实 → 用户选择”主流程，让分类概览成为可操作入口。两种方案：再建分类详情页会分散状态，推荐直接筛选原清单，复用已有目录浏览与预览（KISS/DRY）；处理建议由小型纯函数生成，与界面分离（SOLID），不扩展自动化或删除范围（YAGNI）。

- 点击概览中的可预览、受阻、仅分析分类，跳到原空间清单，并重置用途分类为全部，避免两个条件交集造成误解。
- 原清单增加全部/可预览/暂不可处理/仅供分析/零观测状态筛选，显示各类数量；可与原用途分类组合。两个筛选维度均可通过键盘操作。
- 筛选不会自动选择或清除选择。全选仅影响当前可见的合格项，保留其他选择；清理栏明确显示当前筛选外仍有多少项已选择。预览继续完整列出全部所选对象。
- 项目详情按完整性和规则事实展示下一步建议，不解析中文错误消息推断进程身份或工具状态。读取不完整提示重扫/核对权限，其他受阻项要求先核对原始原因；若涉及程序，先保存工作再自行处理，不自动杀进程或提权。
- Ollama 模型提示先检查项目引用并使用模型管理工具；Docker 提示区分镜像/容器/数据卷；下载文件逐项确认来源、用途和备份。其他只读规则提醒不开放清理，不把“只读”当作“无用”。
- Ollama 详情可进入已有项目账本；目录查看沿用原只读浏览。没有模型引用不代表没有依赖，建议不承诺全部恢复。
- 本轮仅基于已存在的 Item 字段给处理说明，不新增扫描、文件读取、后端命令或删除权限。

验收：概览到清单联动、类别重置、双筛选、可见全选、隐藏选择提示、预览内容、只读禁选、处理建议、项目页跳转、无自动操作、最小 960px 布局以及旧清理回归通过。

### 可清理空间分析：0.6.0（已交付）

根据用户纠正，撤销“输入希望释放空间”主流程。系统先扫描实际存在的数据、识别用途和处理条件，再列出观测到的可执行缓存，由用户选择；不根据期望数字反推“垃圾”或扩大清理范围。

采用分类概览加逐项预览，而非只提供长列表：前者先解释哪些能处理、哪些受阻、哪些只能分析；原清单保留详细目录与手动多选。复用同一资格判定（DRY），分析函数与界面分离（SOLID），不用组合优化器或新依赖（KISS/YAGNI）。

- 可预览缓存：固定 uv/npm/pip 标识、非重复、存在官方命令、无阻止状态、统计完整、无读取问题且有有效正占用。
- 暂不可处理：上述支持的缓存存在运行进程、权限、工具或统计问题；显示原始阻止依据。用户处理原因后重扫，不自动退出进程或提权。
- 仅供分析：项目产物、模型、数据库、Docker、个人文件及其他只读规则不作为垃圾，用户自行判断用途；不为扩大释放量自动删除。
- 支持的缓存若完整测得 0，则单独说明“没有测得正占用”，不当作有阻碍，也不宣称机器没有其他占用。
- 概览只累计合格缓存观测占用；只读和受阻项显示数量，避免与主要目录重叠求和。实际可回收量尚未确定，执行后测量可用空间变化。
- 默认无选择，每项显示恢复影响；uv 特别提示临时工具环境。单项预览和原手动多选共用后端计划，仍需确认，60 秒令牌及执行前复核不变。
- 扫描超过 30 分钟禁止新分析入口预览，提示重扫；清理后扫描结果失效。部分扫描只允许独立完整的合格缓存，并提示可能遗漏。
- 不保留目标输入、达标策略、目标缺额或“为了达到目标自动扩范围”等逻辑。

验收：分类与合计、只读/运行受阻/不完整/零占用/非法数据、默认无选择、单项预览、取消、确认、过期、无合格项和真实释放结果提示通过。既有清单多选资格与新面板一致。

### 空间矩形树图：0.5.0（已交付）

新增「空间地图」，保留既有关系图为默认视图。地图只消费 ProjectReport，表达已识别产物的分配块观测，不代表项目总大小、磁盘占比或可释放量。与关系图形成“找大项 → 展开产物 → 查看影响与项目关系”的路径。

两种方案：内置确定性二分矩形划分（推荐），面积可核验、无新增依赖；引入通用图表库可提供更多布局和动画，但会扩大体积及维护范围，本轮不采用。KISS/YAGNI：只做项目/直接产物两层及小项聚合；SOLID：布局函数与 React 展示分离；DRY：复用现有报告、大小格式及关系图。

- 项目权重为已识别直接产物观测字节之和。共享模型、全局缓存及未测量内容不加入面积；跨产物/项目硬链接、APFS 克隆可能重复，合计明确标为可重复的观测合计。
- 颜色表示 Node、Rust、Python、其他/混合项目；产物沿用所属项目颜色。色彩之外同时显示名称、路径、字节与文字列表。
- 每层最多展示 30 个最大正占用对象及一个「其他项目」聚合块；聚合块保留所有剩余权重，点击可继续展开。文字列表保留所有项目，支持搜索和每批 50 项，零占用对象仅在列表出现。
- 矩形按权重比例二分，沿长边切分，稳定排序；不得为小项设最小面积导致占比失真。图中极小文字隐藏，完整名称仍由按钮标签、提示和等价列表提供。
- 点击项目进入其直接产物层，点击产物显示统计完整性、恢复说明与所属项目。聚合页和项目页提供逐级返回与回到全部项目。
- 项目或产物详情提供「查看项目关系」，打开同一项目的直接关系图；不由空间大小推断依赖。
- 部分扫描统一提醒面积基于当前观测，可能低估；不将未发现对象等同于零占用，不计算未测量模型空间。零数据、空项目、极小项均有明确文本入口。
- 地图不增加扫描、存储、进程控制或删除权限；仅由明确点击才进入现有视图，不调用清理接口。

验收：矩形边界合法、无重叠、面积守恒、面积比例对应权重；输入次序不影响布局；聚合前后权重守恒；同名不同路径不合并；零/负/非有限输入不生成错误面积；项目展开/返回/搜索/分页/键盘/关系跳转/部分结果/空结果、960px 布局通过。原三套界面检查继续通过。

### 图形关系展示：0.4.0（已交付）

在项目账本内新增「关系图 / 账本列表」切换，默认关系图。关系图回答“已发现什么关联”，账本继续用于精确比较分配空间。两种方案比较：固定列直接关系图易读、无需新依赖，优先实施；全机自由布局图适合探索大量关联，但会混淆关系层次，当前暂缓。矩形树图适合比较大小，不用于表达依赖，本轮不实现。

- 左侧选择项目，支持名称/路径搜索与分页；中心展示选中对象的一层关系，右侧（窄窗口下方）展示对象或连线的证据。
- 节点：项目、已测量产物、已安装 Ollama 模型、可见 PID。模型以运行器和模型名去重，进程以本次报告的 PID 去重，产物以项目路径和直接子目录名标识。
- 三种有方向的连线：项目 → 产物「目录包含」、项目 → 模型「配置引用」、进程 → 项目「可见路径引用」。颜色、线型、文字图例共同区分，不能只依赖颜色。
- 点击节点将其设为中心，只展示直接邻居；点击共享模型可看到同一报告内引用它的多个项目。点击连线在详情中显示配置文件名或 PID 依据。提供「返回所选项目」，不提供全图无限展开。
- 运行进程目前只能关联项目，不能由项目级路径线索推断进程正在使用某个产物或模型。嵌套项目的祖先路径匹配也不代表直接调用。
- 产物显示分配空间及完整性，详情显示恢复条件。模型占用没有单独测量，明确写「占用未测量」；不将模型/共享缓存大小重复计入项目，不展示“可释放总量”。
- 未发现关系显示检测边界，不画“未使用”“可安全删除”节点或标签。部分扫描显式标记；关系只覆盖本次扫描范围，未扫描项目可能仍有引用。
- 新版 Evidence 增加可选 model、source、pid 结构字段；界面不解析 message 推断身份。不带结构字段的旧数据仍可作为文本说明，但不生成模型/进程连线。
- 图与文本关系清单等价；节点、连线均可键盘聚焦和选择。邻居默认每批显示 12 个，可继续显示，连接路径不参与自动避让、物理模拟或拖拽。使用现有 React、SVG 和 CSS，不新增依赖。
- 关系图仅消费 ProjectReport，不新增文件访问、基线持久化或清理权限；详情不显示命令行或配置正文。

验收：多个项目引用同一模型只生成一个模型节点；不同路径同名项目不混淆；多个配置引用同一模型合并连线并保留来源；PID 去重；缺少结构字段不臆造关系；节点切换、连线证据、直接关系分页、键盘、空报告、部分结果及最小 960px 宽度通过检查。原账本与清理流程回归通过。

### 第一阶段：证据与账本（已交付 0.3.0）

- 独立项目页，不依赖数分钟全盘扫描；识别 package.json、Cargo.toml、pyproject.toml、requirements.txt。
- 同一项目可识别多种语言；继续发现嵌套项目，但跳过 .git、依赖、虚拟环境和构建目录。
- 测量 node_modules、target、.venv、venv、dist、build、.next、__pycache__ 等已知直接子目录；明确全局共享缓存不分摊到项目。
- 仅主目录内部、无路径符号链接、同文件系统扫描；限制深度、目录数、产物数和总扫描时间，取消/权限/上限均标为部分结果。
- 从可见进程的绝对路径参数识别项目或产物路径引用，只显示 PID 与证据类型，不回传命令行、环境变量或配置内容。
- 读取有限的项目根配置文件，针对已安装 Ollama 模型做名称精确边界匹配；只回传模型名称、相对配置文件名，不保存文件内容。
- 保存每工作目录最新一次完整扫描的产物占用基线；部分扫描不覆盖完整基线。变化只表达目录观测，不推断进程写入者或“长期未使用”。
- 项目页清晰标识只分析；缓存清理入口复用旧执行器，禁止将项目路径传入删除命令。

### 第二阶段：受保护的项目清理

- 为每项产物生成后端不可变 ID 与文件身份；扩展计划和历史，不接受前端任意路径。
- 先支持经验证可重建的 Node/Rust 产物，Python 环境必须检查可重建配置，缺少锁文件或依赖源不可达时提示恢复限制。
- 删除前保护 Git 跟踪文件、嵌套仓库、符号链接、其他卷、运行中环境；Git 或进程检查失败则拒绝。
- 不运行项目脚本或生命周期钩子；使用描述符相对操作防止路径交换，不用拼接 shell 或通用递归删除。
- 预览 60 秒有效、单次使用；执行前与逐项执行时复核，失败停止，保留已完成结果。
- “恢复”需有确实备份才可承诺。移入同卷废纸篓不计作释放空间；永久删除必须明确确认。

### 第三阶段：持续变化与增长归因

- 先分析实际数据，按用途、运行状态、引用证据和恢复条件展示可处理范围；没有合格数据时明确说明，不追逐人为释放目标。
- 共享数据和快照导致的可回收量不确定时不作精确保证。
- 多次历史与增长趋势、主动扫描对比、清理后回涨追踪；后台采样需另行设计用户开关。
- Docker、数据库采用官方对象接口只读建模，再逐项开放操作；禁止按数据目录直接删除。

## 数据与技术设计

新增 projects 模块管理 ProjectReport、Project、Artifact、Evidence、Change。Engine 继续管理任务互斥和取消；项目模块调用既有分配块测量及路径验证。Tauri 增加 scan_projects(root) 命令，前端增加 ProjectLedger 组件，原清理 IPC 保持兼容。

ProjectReport 包含规范化工作目录、测量时间、完整性、读取问题、限制说明、项目列表、上次基线时间及变化。Artifact 包含直接子目录名、分配字节、条目数、完整性和恢复说明；缺少锁文件等恢复限制在此说明。Evidence 明确类型：可见进程路径引用、模型配置引用、未知依赖。

基线写入应用数据目录 projects.json，最多保留最近 20 个工作目录，每目录最多 5000 个产物键。仅存路径、大小、时间；不保存源码、配置正文、进程参数、密钥。先写同目录临时文件再原子替换；校验基线目标路径，读取失败明确警告，不伪装成首次扫描。

扫描上限：深度 8 层、20,000 个发现目录、1,000 个项目、5,000 个产物、总预算 120 秒；单配置 64 KiB；基线文件最多 16 MiB；部分结果不可作完整基线。界面每批显示 50 个项目。分配块统计可受 APFS 克隆/快照影响，跨项目硬链接可能重复，因此不把项目合计当作可释放总量。

## 工程原则与风险

- KISS：规则识别、有限配置匹配，不加 LLM 或关系数据库。
- YAGNI：本阶段不做项目自动删除、系统加速、云盘、照片、后台常驻。
- SOLID：项目发现/证据模块与现有执行器分离；执行器继续负责删除边界。
- DRY：复用路径校验、磁盘统计、任务锁、取消和现有清理闭环。
- 关系图采用确定布局与内置 SVG（KISS），本轮不加矩形树图、物理模拟或全机无限展开（YAGNI）；图数据与展示分离（SOLID），复用报告与恢复说明（DRY）。
- 进程不匹配不等于没有依赖；相对参数、进程工作目录、动态配置未覆盖。
- 配置引用不证明真实调用，也不证明模型独占；缺少引用不证明可删除。
- 配置文件读取只在本机完成，界面不回显正文；文件系统变化使扫描不是原子快照。

## 验证策略

临时目录构造混合与嵌套项目、伪目录、链接和外部哨兵、硬链接、缺少锁文件、模型名称边界、进程路径边界、取消和超限场景。基线验证首次/增长/新增/消失、工作目录隔离、损坏和链接保护、部分扫描不覆盖。运行 Rust 测试、Clippy、TypeScript 生产构建、模拟 IPC 界面流程及本机工作目录只读扫描；不清理用户真实项目来验证功能。

### 0.8.0 扫描前范围与权限

所有磁盘扫描先选择范围，默认只统计 uv、npm、pip 的默认缓存。扩展扫描继续覆盖原有主要目录和应用数据，需要先阅读权限要求。项目扫描单独展示输入目录并确认。取消不触发扫描。

系统授权由 macOS 管理：提供系统设置入口，不伪造完全磁盘访问检测，不把确认阅读当作已授权，不因返回设置自动启动扫描。常规扫描不查询或追踪自定义缓存路径，清理预览仍核对工具实际配置。受拒绝目录计入读取失败。

方案取舍：采用按需扩大范围；不采用首次启动强制要求完全磁盘访问，减少不必要授权。使用已有命令和弹窗模式，保持 KISS、YAGNI、DRY 和职责边界。系统用途说明由 Info.plist 合并到应用包。

### 0.8.1 统计不完整后的恢复

扩展扫描前可展开具体根目录，常规扫描展示三个默认缓存路径。磁盘扫描后将不完整条目集中展示名称、路径、读取问题数及原始阻碍；取消时明确未访问目录尚未计入结果。失败不一概归为权限问题，不合计重叠目录失败数。

结果提示提供系统设置入口，打开失败就地反馈。用户处理权限后手动重新扫描，避免自动重试再次触发系统提示。不增加系统权限探测，不改变扫描或清理规则。

### 0.8.2 集中授权指引

扩展扫描优先引导用户到完全磁盘访问设置，分步说明用途、如何添加应用和何时重启。设置入口尝试定位目标页面，失败回退系统设置主页，始终展示手动路径。Finder 定位由当前进程可执行文件推导 .app，不接收用户提供的路径；开发构建无法定位时给出明确提示。

系统授权仍由用户操作，界面始终显示「未验证」，不因为打开设置、定位应用或确认阅读改变授权状态。常规扫描继续默认，无需先授予完全磁盘访问；所有扫描仍须手动开始。更新签名、系统版本及文件保护差异可能导致再次授权，不能保证永久无弹窗。

### 0.8.3 其他应用数据扫描边界

实机截图表明集中授权引导未解决全部提示。扩展扫描改为在读取前主动排除常见 Library 私有数据路径，包括应用容器、共享容器、Application Support、邮件、消息、Safari 等。固定规则、递归测量、目录展开、自定义缓存与项目扫描共用路径边界；本应用专用历史和基线接口不受影响。

主动跳过不记为系统读取错误，被跳过目录标记未读取；父目录统计为下限。Docker、企业微信容器不再默认分析，界面明确说明覆盖下降。采用收紧边界而非继续扩大授权，遵循最小访问、KISS/YAGNI 和共享校验 DRY；不保证枚举所有系统保护路径。

### 0.8.4 视觉与交互层级

首页以「磁盘空间」和扫描、结果、确认清理三个阶段组织信息。扫描前以两张卡片选择常规与扩展范围，详细路径和授权教程折叠；权限入口保持可见，状态不伪造为已授权。扫描弹窗的标题与底部操作固定，长内容仅在中部滚动。

结果页先给建议，再按需查看不完整位置和处理方式。其他目录占用及统计说明默认收起；只有已选择清理项才出现底部操作栏。默认不勾选，仍须预览、确认和执行后核验，不改变任何扫描或删除保护。

风格沿用米白与绿色，用明确标题、短文案、字号和留白建立层级，不增加装饰与依赖。复杂关系图和空间图保留原交互，本轮只统一页面标题。

### 0.8.5 结果页精修

顶部保留候选总占用，分类卡只展示数量。可预览缓存采用紧凑横向行呈现名称、占用、恢复影响和预览入口；uv 特殊影响保持可见。列表状态直接使用同一分类标签，避免“可清理”和“可预览”混用。

候选卡提供可预览筛选入口。空筛选可一键清除，保留原选择；取消选择只清空选择，保留筛选。两种操作都不进入清理。列表名称和路径提高字级，状态增加清晰的中性色与受阻提示，并支持减少动态效果的系统偏好。没有新增扫描或删除能力。


### 0.9.0 只读模型空间账本

项目扫描沿用已有任务锁、取消及进度机制，同时分析默认 `~/.ollama/models` 仓库，不启动 Ollama、不读取模型正文、不增加删除命令。清单解析与归属汇总独立于缓存清理执行。项目扫描前说明这一额外固定范围，自定义仓库暂不支持。

ProjectReport 增加可选 modelStorage，旧数据兼容；模型统计与项目统计各有完整性。默认仓库中按设备号和 inode 合并文件，模型与文件块引用去重。全库只统计已被读取清单引用的文件，不包括未引用文件、目录开销和清单本身。展示逻辑大小及分配空间；单模型关联占用可重复，不跨模型相加或分摊到项目。

独占只表示本次完整读取的清单范围内没有其他模型引用，不是物理独占、没有依赖或可回收保证。缺块、坏清单、超限、取消时全局隐藏独占结论；未归属硬链接使相关模型的独占不可确认。APFS 克隆和并发变化仍是测量盲区。

模型账本默认折叠，支持搜索、每批 20 项及文件块依据展开；项目配置引用复用已有证据，点击切换至对应关系图并定位焦点。图中有可匹配测量值时显示关联占用，旧报告仍显示未测量，不根据文字猜测身份。

扫描限额与路径保护、方案取舍见 [模型空间账本设计](plans/2026-10-20-model-storage-design.md)；实际验证见 [验证记录](verification.md)。


### 0.9.1 模型账本可靠性与详情展示

模型遍历队列只保存相对名称，每次从固定清单根目录描述符逐级禁止链接打开，不再为兄弟目录积压句柄。原有总条目、模型数、引用数和读取预算不变。测试在独立子进程设置 64 个文件句柄额度，完整扫描 200 个共享块模型，并验证根替换后仍读取固定位置、中间链接仍被拒绝；不修改应用或系统资源额度。

折叠的模型账本摘要直接显示统计不完整或已停止。文件块依据只有展开时才生成列表，每批 50 条，折叠后移除列表并重置分页；模型搜索和项目跳转沿用既有行为。没有新增清理、授权或仓库范围。详细证据见 [本轮计划](plans/2026-10-20-model-ledger-hardening.md) 与 [验证记录](verification.md)。


### 0.9.2 清理依据与核验

首个样板为本项目独立定义的 `dev.uv-cache` 第 1 版规则，不使用 CleanMyMac 反编译代码或尚未读出的规则库。后端生成来源、范围、恢复条件和保护状态，前端在现有清单详情及确认页展示；默认路径观测与工具配置确认分开说明，自定义目录仍只读。

用户可持久化保护整个 uv 默认缓存根目录。保护不阻止只读扫描；设置损坏或读取失败时阻止 uv 清理，设置变更使旧计划与扫描失效。官方整目录命令没有受验证的子路径排除接口，因此不提供误导性的部分排除。

uv 元数据摘要包括路径、设备、inode、模式、长度、分配块、修改／状态时间和硬链接数，不读取正文；从扫描到预览及执行前比较，发现变化或统计不完整时拒绝继续。摘要不是密码学内容校验或原子锁，最后复核后仍可能出现并发变化；运行进程与安全路径检查继续生效。复核限制 45 秒和已有条目上限，不能完成就拒绝，不扩大权限或终止进程。

所有扫描目标携带结构化覆盖信息；取消后保留已知未访问目标，主动跳过与权限拒绝分别记录。只有确实收到权限拒绝才在结果中提供设置入口，旧格式没有分类时不猜测原因。覆盖完整仍仅指选定规则范围，不代表整盘覆盖。

所有执行项区分成功、失败、跳过；前一项失败后剩余项明确标记未执行。uv 命令后复测目录，命令状态与复测结果独立，保留剩余数据或核验失败事实；其他类别暂未逐目录复测。历史和结果共用组件，根据前后可用空间展示增加或减少，磁盘核验失败时不展示伪造的零变化。`released` 字段仅为旧数据兼容保留。

KISS／YAGNI：先做一类缓存闭环，不引入通用规则编辑器、后台服务或更多清理类别。SOLID／DRY：后端保存可信依据与内部摘要，界面共用资格、依据和结果组件。具体实现与验收见 [计划](plans/2026-10-21-cleanup-trust.md)、[验证](verification.md) 和 [修改记录](change-log.md#change-20261021-002)。
